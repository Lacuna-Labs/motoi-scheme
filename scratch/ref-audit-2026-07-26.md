**THE LINE (verified, to state in prose):**
- **Local game-AI** (`ai/seek`, `ai/bt-*`, `ai/path`, etc.) runs on the bare console — no external anything.
- **Model-backed AI** needs an external model/LLM **sidecar** (a separate process). Two degrade shapes:
  1. `llm/*` returns **`#f`** when no backend (`llm/config` → `((:backend none))`).
  2. `ai/generate|classify|summarize|translate|rank|rerank|vector-search` **raise** `(<verb> …) requires-python-ml-sidecar` — an intentional honest error (the sidecar isn't a fallback; local would be arbitrary).
  3. `copilot/*` and `copilot/what-is` blend registry/reference lookups (work offline) with an `:llm-hit` that is `#f` offline — they degrade to their non-LLM parts.
- Sidecar is set via `:ai-provider` in `scheme-lang.config.slat` or `setAiProvider({llm:…})` at startup.

Plan: expand `02-ai.slat` with a model-verbs section drawing this line explicitly; every example runs headless (catches `#f` / the raise).

TWO RUNTIME GOTCHAS discovered + documented in the chapter caveats:
1. cpu/state and cpu/opcodes records use 2-ELEMENT-LIST cells `(:key value)`,
   so the accessor is `(cadr (assoc :key rec))` — NOT `(cdr ...)`, which yields

2. cpu/opcodes and cpu/disassemble return mnemonics as Sym objects that are
   NOT eq?/equal? to reader-quoted symbols and where `symbol?` returns #f —
   compare via `(symbol->string m)` against a string. (cpu/step!'s returned
   symbol IS eq?-comparable — different construction path.)
